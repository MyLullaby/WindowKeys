# WindowKeys

[![Build](https://github.com/MyLullaby/WindowKeys/actions/workflows/build.yml/badge.svg)](https://github.com/MyLullaby/WindowKeys/actions/workflows/build.yml)

一个包含六个窗口动作的原生 macOS 菜单栏工具，编译目标为 Apple Silicon（arm64）。

| 动作 | 全局快捷键 |
|---|---|
| 只按自定义宽高比例调整大小 | Control + Command + C |
| macOS 原生居中 | Control + Command + ↓ |
| macOS 原生填充 | Control + Command + ↑ |
| macOS 原生左半屏 | Control + Command + ← |
| macOS 原生右半屏 | Control + Command + → |
| 进入/退出 macOS 原生全屏 | Control + Shift + F |

Control + Shift + F 切换当前窗口的系统全屏状态（独立 Space），不是最大化填充；
再次按下退出全屏。通过窗口的 `AXFullScreen` 属性请求系统处理，不自定义尺寸或动画。
窗口不支持此属性时会提示音并记录日志。

六组组合键通过 macOS `RegisterEventHotKey` 注册为全局快捷键，成功注册后由 WindowKeys
独占，前台应用不再同时收到同一组合键；普通方向键、C、F 不受影响。按住组合键只触发一次，
松开后可再次触发。即使窗口动作不可用，也不会将已接管的组合键转发给应用。
如果系统或其他全局快捷键工具已占用组合键，启动时会列出注册失败的动作；需要解除占用并
重启 WindowKeys，失败项不会静默退回监听模式。无需修改前台应用普通的同名快捷键。

四个方向键优先触发目标应用的 macOS 原生窗口菜单命令，系统负责动画和台前调度。
如果目标应用没有暴露对应菜单、菜单禁用或辅助功能调用失败，WindowKeys 会回退到公开的
macOS Accessibility API 回退。居中只需窗口位置可设置，因此支持“位置可移动但尺寸只读”的窗口，并以约 0.3 秒动画移动；
填充和左右半屏仍要求位置与尺寸都可设置。回退沿用系统“平铺窗口边距”设置。应用可拒绝/限制
AX 写入，且不同应用的最小尺寸、窗口约束不同；WindowKeys 会核对实际结果并记录失败原因。
若原生菜单调用报告成功但应用实际未执行，
当前仍以系统结果为准，不会重复移动窗口。无法通过公开 API 保证所有应用/窗口都可控；全屏
仍只请求系统原生 `AXFullScreen`，不模拟全屏或跨 Space 操作。

只有 C 的“调整大小”使用自定义实现：通过 AppKit `NSAnimation` 执行约 0.3 秒的
尺寸动画，只写窗口大小，不写位置、不自动居中，也不进行结束后的位置补正或尺寸重试。
需要居中时，再按 Control + Command + ↓；优先使用原生命令，不支持时回退到仅移动窗口位置。
窗口的最小尺寸、屏幕边缘限制及系统平铺恢复行为仍由目标应用和 macOS 决定；C 不会通过
移动窗口来绕过这些限制，因此不保证所有窗口都能达到指定比例或绝对保持原位置。
新动作或焦点变化会取消旧动画。菜单栏中的“窗口调整动画”控制 C 和自定义居中回退；
关闭该选项或系统开启“减少动态效果”时，这两个动作直接调整，原生命令仍遵循系统自己的动画设置。
保留原有的动画开关和宽高比例配置。增强辅助功能模式（`AXEnhancedUserInterface`）不覆盖动画开关：
原本开启时，在调整期间临时关闭，动画完成、取消、失败或应用正常退出时恢复并检查；
恢复失败会记录日志。只有关闭动画开关或启用系统“减少动态效果”才走直接调整路径，
直接调整路径仅发送一次尺寸请求。
菜单栏中的“开机自动启动”使用 macOS 登录项机制，可随时开启或关闭；如果系统要求批准，
应用会引导到“系统设置 → 通用 → 登录项与扩展”。

## 选词翻译（CB-proxy）

先在 Mac 启动 CB-proxy（`http://127.0.0.1:8787`），在其他应用选中文字，
按 **Option + D** 或点击菜单“选词翻译…”。浮窗上方显示原文，下方显示译文。
该全局快捷键注册成功后会优先于前台应用的 Option-D（包括键盘布局中该组合键的字符输入）。
需要辅助功能权限；不支持读取选中文字的应用，可直接在原文区域粘贴文字后点击“翻译”。
取词不会模拟复制或覆盖剪贴板；“复制译文”按钮才会主动写入剪贴板。

模型下拉列表从代理的 `/v1/models` 获取，默认 `codebuddy/claude-haiku-4.5`。
选择其他模型后点击“翻译”，选择会保存，不改变 Codex 的模型配置。
中文默认译成英文，其他语言译成简体中文；单次最多 20,000 字符，超时为 120 秒。
需要 Mac 本机代理和对应模型权限；Linux 代理可用不代表 Mac 已配置。
窗口关闭或原文/模型改变时会取消本地等待，代理上游请求不保证同步停止。

只有主动触发翻译才发送原文。代理通常会转发到远端模型，因此不是离线翻译。
WindowKeys 不记录原文、译文或保存翻译历史；CB-proxy 及上游服务的日志、留存规则独立，
请避免提交敏感内容，并检查代理是否开启完整请求日志。应用无需读取 Codex 密钥。

开发验证：在 macOS 执行 `zsh Tests/run-translation.sh` 检查请求构造与响应解析，
再手动验证选词、粘贴、模型切换、代理离线及关闭窗口后重新翻译。

## 本地诊断日志

菜单栏勾选“保存诊断日志”后复现问题，再点击“导出诊断日志…”选择桌面或其他位置，
即可保存一个 `.txt` 文件用于反馈。默认关闭，开关会跨重启保留；关闭后停止追加，但仍可导出已有记录。
日志只保存在本机，不会联网上传。不记录输入内容、剪贴板或窗口标题；包含应用和输入法标识、
操作时间、系统版本、权限状态和操作错误，分享前可自行查看。
内部文件位于 `~/Library/Logs/WindowKeys/`，按约 1 MiB 轮换，最多保留两份。
普通日志不是系统崩溃报告，无法保证记录崩溃堆栈；闪退后可重新打开应用导出此前已写入的记录。
如仍无法启动，可从上述目录手动取出日志。未开启记录时，导出只包含基本状态及历史记录。

## 按应用切换输入法

在菜单栏选择“应用输入法设置…”可以设置一个默认输入法，并为指定应用添加专属输入法。
自动切换默认关闭（升级后尚未设置开关时也关闭），需在菜单栏勾选“自动切换输入法”才能生效。
关闭时保留全部配置，不初始化自动切换管理器、不监听应用切换，也不执行待开始的切换；
已经发出的按键序列会完成松键，避免按键卡住。窗口快捷键不受影响。
若开启后无法启动，可在 Mac 终端执行以下命令关闭此功能，再重新启动新版应用（不会删除规则）：

```sh
defaults write com.bland.windowkeys inputMethodSwitchingEnabled -bool false
```

切换应用时优先使用该应用的专属配置；没有专属配置时自动使用默认输入法。
首次开启且未设置默认值时，会把当时正在使用的输入法保存为默认值，之后可以随时修改。

先切换到需要配置的应用，再打开“应用输入法设置…”并点击“添加当前应用”，
即可识别并选中该应用的规则，在该行选择固定输入法。设置窗口保持打开时，
也可以切换到其他应用后返回再添加。识别会排除 WindowKeys 自身；重复添加不会覆盖已有配置。
新规则初始使用默认输入法（不可用时回退到当前或可用输入法），也可以通过“添加应用…”手动选择应用。

应用规则按 Bundle ID 匹配，因此移动或更新应用后仍然有效。删除某条专属配置后，
对应应用会重新使用默认输入法。如果配置的输入法已被停用或卸载，WindowKeys 会保持
当前输入法不变，并在设置窗口中将该输入法标记为不可用。
WindowKeys 只在当前输入法与目标配置不一致时模拟一次系统“选择上一个输入法”快捷键
（默认是 Control-Space），由 macOS 完成切换。请确保该快捷键已在系统键盘设置中启用；
此方式适合在 ABC 和一个非拉丁输入法之间切换。

在菜单栏选择“C 窗口大小…”可以分别拖动宽度和高度滑块。两项均以当前屏幕的
可用区域为基准，可在 30%–100% 之间按 1% 调节，修改后自动保存。
应用使用公开的 macOS Accessibility API，
不会调用 AppleScript，也不会包含 Intel/Rosetta 代码。

## 构建

```sh
./build.sh
```

每次向 GitHub 推送提交以及创建或更新 Pull Request 时，GitHub Actions 都会自动构建并校验
Apple Silicon 版本。可以在仓库的 [Actions](https://github.com/MyLullaby/WindowKeys/actions/workflows/build.yml)
页面打开对应的构建记录，并在页面底部的 **Artifacts** 中下载 `WindowKeys-macos-arm64-<提交哈希>`。
也可以在 Actions 页面通过 **Run workflow** 手动触发构建。构建产物保留 30 天。

首次启动后，在“系统设置 → 隐私与安全性 → 辅助功能”中允许 WindowKeys。

## 窗口回归验证

打开待测窗口后运行（执行环境需要辅助功能权限）：

```sh
zsh Tests/run-window-commands.sh com.tencent.WeWorkMac '文档窗口标题'
```

只检查快捷键映射和动画状态恢复、不操作窗口时，可运行（保留原脚本参数）：

```sh
zsh Tests/run-window-commands.sh --geometry-only
```

脚本调用当前源码的窗口控制器，检查快捷键映射、动画状态恢复、普通窗口缩放时保持位置、
自定义尺寸动画及结束后的稳定性、
最大化、退出平铺后的缩放、单次居中和动画中断。原生命令测试需要应用支持相应菜单。
系统原生平铺的边距可配置，用例会读取当前设置，而非要求固定 8 像素。
结束后恢复原窗口尺寸和位置。测试期间请勿切换窗口；前台变化会中止后续命令。

快捷键独占需要在 macOS 实测：在编辑器或列表中按 Control + Command + ↑，确认只有窗口
动作、不发生应用内导航；单独按 ↑ 仍正常导航。还需验证长按不重复触发，以及另一全局工具
占用组合键时，启动会显示注册失败提示。几何测试脚本不验证系统实际的按键投递。
